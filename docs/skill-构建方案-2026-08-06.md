# automotion-v7 skill 构建方案

> 日期：2026-08-06
> 状态：已与用户对齐（brainstorming 完成），待用户审阅本 spec
> 目标：构建 automotion-v7 —— 通用的、自动化的口播视频成片 skill

---

## 1. 目标与定位

构建一个可用的 automotion-v7 skill：用户提供**文案 + 录音**，skill 走完「转录/分段 → 工作台定稿 → 整片预览 → 导出」流程，产出**任意主题口播视频**的成片（1920×1080、30fps、mp4，自然时长，带字幕，无 BGM）。

- 本仓库（automotion-v7）= skill 工具本体（镜头库/数据模型/匹配/工作台/合成）
- skill 本体 = 对这套工具的封装说明（SKILL.md），最终放 `~/.codex/skills/`（与 automotion-v4/v5 同级）
- 顺序：先修好并跑通工具（阶段 1-5），最后用 skill-creator 封装（阶段 6）

## 2. 已对齐决策（前提）

| 项 | 决策 |
|---|---|
| 输入 | 文案 + 录音（口播视频两大素材） |
| 范围 | 任意主题的口播视频（不含产品 showreel / 纯转场片） |
| 视觉风格 | 纸墨风固定；风格控制模块独立（`_system/colors.ts` 为唯一风格权威），为后续版本替换风格预留边界；v7 不做多风格 |
| 输出 | 1920×1080 横屏、30fps、mp4、自然时长 |
| 自动化 | 转录、分段、匹配、导出自动；分段结果在工作台可人工调整 |
| 人工介入 | 工作台定稿（分镜 + 字幕样式）、整片预览验收（发现问题回工作台改） |
| 匹配理念 | 无「能不能用」概念：不做准入/排除/禁入，只有匹配度（M3 专题讨论具体机制） |
| 可用性分级 | 「可用/疑似/不可用」彻底抛弃 |
| 项目数据 | 013 等具体项目数据不进 v7 仓库；测试用隔离环境真实文案（项目侧 013B）；端到端验收用真实录音（项目侧） |
| 路线 | 修不重做（M1 成果 166 提交 / 3 万行可复用） |

## 3. 构建路线（6 阶段）

### 阶段 1：M1 修复（污染清理 + 文档重写 + 机制补漏）

**1.1 代码污染清理**
- 8 个真实使用演示组件的镜头（TitleBlock ×3：CelFlashStomp / MaskingTapeSlap / RisoMisregistrationHit；Card/FakeDashboard 相关：LineUnfoldPanel / KeycapSmashCut / AttentionBounce / GridWaveFlip / UiStripAwayOutro）→ 换中性渲染
- 11 个仅残留 import（`import { G, TitleBlock }` 未使用）→ 删 import
- 4-5 处品牌默认值（Notion AI / perplexity / ClickUp Space / Find in Slack 等）→ 换中性默认值
- `_fixtures/Fixtures.tsx`：删除 FakeDashboard / Card / TitleBlock 导出；**保留 G 色板中转**（152 个组件文件的 import 不动；`_system/colors.ts` 为唯一风格权威，`_fixtures` 仅转发）
- 注释里的品牌来源（150+ 文件的「对标 clickup-30 / notion-ai」等）：**保留**（历史来源记录，不影响运行与画面）

**1.2 风格模块独立**
- `_system/` 为唯一风格权威（色板已独立；字体/纸纹等风格相关如有散落归入 `_system`）
- 为后续版本替换风格预留清晰边界（不实现多风格）

**1.3 补污染扫描机制**
- 新增 `scripts/scan-pollution.mjs`：扫描演示组件真实使用、品牌默认值、项目内容词
- M1 验收标准改为：污染扫描 0 命中 + 全量渲染 165/165 + 用户抽查 8-10 个镜头预览
- **不再靠声称，靠扫描报告**

**1.4 文档重写（v7-组建文档.md）**
- 定位改「automotion-v7 skill 构建蓝图」，明确最终目标
- §11 M2 重定义（数据模型，不预设字段、不引 013）
- 概念清理：删「池/禁入/排除/准入」残留；§6 匹配改为方向声明 + 待 M3
- 数字口径统一：注册 165 / 命名 167 / 组件 162；删旧「146 / 169」
- 013 判定改「项目数据，不进 v7 仓库」；§5.3 删 283 SRT 样本引用；§9 删 283 SRT
- §10 目录：`storyboards/` → `samples/`（隔离中性样本）
- lens-names.md 删「可用性」列
- 参数化设计规范：适用范围改「方法论（M1 已应用）」

**1.5 小修**
- remotion.config.ts 中文注释乱码修复
- engine 迁移：`lenses/engine/` → 根 `engine/`（共享资产，组建文档原设计；改 CardFlipReveal 的 import）

**验证点**：污染扫描 0 命中 + 全量渲染 165/165 + 用户抽查预览

### 阶段 2：M2 数据模型

- `shared/types.ts`：镜头注册 / storyboard / 字幕 / 转录 的类型定义
- `shared/registry.json`：165 全量注册数据（id / 中文名 / 组件路径 / 分组 / 参数 schema 自动提取）；**语义画像字段留给 M3**
- storyboard、字幕、转录的 schema（只定义结构，不引入 013 数据）
- 测试数据：用隔离环境真实文案（项目侧 013B），不做中性假样本

**验证点**：类型检查通过 + registry 与 Root.preview 注册一致 + 真实文案（隔离环境 013B）可被 schema 校验

### 阶段 3：M3 匹配系统 —— ⚠️ 留空，最着重讨论的专题

本阶段在方案中**不做任何机制预设**。候选的方向约束已对齐（无准入、纯匹配度、可审查理由），具体机制（输入特征、打分模型、输出形态）在 M3 开工时从零专门讨论。

**验证点**（待 M3 讨论时确定）：匹配结果可审查

### 阶段 4：M4 工作台

- client 三栏布局：左栏段列表 / 中栏参数表单 + 预览 / 右栏推荐区 + 镜头库（hover 预览、可伸缩）
- 两环节：分镜定稿、字幕样式
- **保存式交互**（非向导式）：镜头调整与字幕调整均有「保存」按钮，保存一次更新一次文件；「进入下一步」由用户与 skill 的对话交互决定（如用户说「去预览」）；预览发现问题随时回工作台改、再保存
- 预览：@remotion/player + 单镜头渲染 + 增量缓存（RENDER_VERSION | lensId | params | frames）
- 预览展示镜头效果与参数调整（非真实时长）；真实时长 = 刚性 + 弹性对齐段时长

**验证点**：换镜头自动填参

### 阶段 5：M5 合成

- 消费 storyboard + 字幕数据 → 整片 Sequence 串联 + 字幕层 → 整片预览（验收）→ 导出 mp4（1920×1080@30，无 BGM）
- 增量原则：预览发现问题 → 回工作台改对应镜头 → 只重渲染该镜头，其余复用缓存

**验证点**：端到端跑通（用用户提供的真实录音，项目侧数据）

### 阶段 6：skill 封装

- 用 skill-creator：SKILL.md（触发词 + 四步流程 + 与用户交互方式）+ scripts / references / assets
- 位置：`~/.codex/skills/`（与 automotion-v4/v5 同级）
- 参考 automotion-v4/v5 的既有结构

**验证点**：quick_validate 通过 + 一次真实任务走通

## 4. 关键取舍（已确认）

| 取舍点 | 决策 | 理由 |
|---|---|---|
| `_fixtures` G 中转 | 保留中转（152 文件 import 不动） | 改动最小，`_system/colors` 仍是唯一权威 |
| 来源注释 | 保留（产品名注释） | 历史来源可追溯，不影响运行与画面 |
| engine 位置 | 迁到根 `engine/` | 引擎是共享资产（匹配/工作台也要用），按组建文档原设计 |
| 端到端验收素材 | 用户真实录音（项目侧） | 真实转录对齐，验证更可靠 |

## 5. 明确不做

- 不引入 BGM
- 不做多套视觉风格（只做风格模块解耦）
- 不用 LLM 对话选镜头
- 不引入 013 等具体项目数据进仓库
- 不恢复「可用/疑似/不可用」分级，不做准入/排除/禁入

## 6. 开放议题

- **M3 匹配机制**（最高优先级专题）：开工时从零讨论，不预设
- skill 触发词与用户交互细节：阶段 6 时定
